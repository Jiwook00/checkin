# 갈피 레터 생성

체크인 회고 모임의 사서 페르소나 **갈피**가 매달 보내는 **회고 다이제스트 레터**(HTML)를 만든다.
발송은 하지 않는다 — 사용자가 프리뷰를 검토한 뒤 직접 보낸다.

**작성 규칙의 단일 출처: [`docs/galpi-letter-guide.md`](../../../docs/galpi-letter-guide.md).**
이 스킬은 그 문서를 실행하는 절차서다. 세부 규칙이 충돌하면 항상 가이드 문서를 따른다.

## 인자

`<session>` 하나 (예: `2026-07`). 없으면 사용자에게 어느 달인지 묻는다.

## 절차

1. **가이드 읽기** — 시작 전에 `docs/galpi-letter-guide.md`를 읽는다. (갈피 목소리·요약 규칙·체크리스트가 거기 있다.)

2. **데이터 뽑기**

   ```bash
   node scripts/export-letter-data.mjs <session>
   ```

   → `letters/<session>/data.json` 생성. 세션이 안 맞으면 스크립트가 존재하는 세션을 알려주니 다시 시도.

3. **ledger 읽기** — `letters/galpi-letters.json`에서 `nextNumber`(마스트헤드 No.)와 `topicsUsed`(이미 쓴 주제 — 다음 달 주제 중복 방지용)를 확인.

4. **요약 작성** — `data.json`의 각 `contentMarkdown`을 **중립 톤 불렛 2~3줄**로 간추린다.
   갈피 코멘트·감상 넣지 않는다. 본문에 없는 내용 지어내지 않는다. (가이드 §4)

5. **댓글 정리** — `data.json`의 `comments[]`를 "누가 → 누구 글에 + 본문"으로 정리. 각 항목 링크는 `{articleUrl}#comment-{commentId}`. 댓글 없으면 그 섹션 생략. (가이드 §5)

6. **다음 달 주제 고르기** — ledger `topicsUsed`에 **없는** 주제 하나를 후보 뱅크(기획 §4-2)에서 골라 예고 섹션에 넣는다. 예시 한 줄 곁들임. (가이드 §5-2)

7. **템플릿 채우기** — `letters/<가장최근세션>/digest.html`을 복사해 `letters/<session>/digest.html`로 만들고, `<!-- SLOT: ... -->` / `CARD` / `COMMENT` 블록을 교체한다.
   - 멤버 카드·댓글 항목은 개수만큼 복제/삭제. `더 보기`=각 `articleUrl`, 댓글=각 딥링크.
   - 마스트헤드 `No.NN / YYYY. MM`, 오프닝 멘트(계절·분위기), 인트로(작성 인원)를 이번 달에 맞게.
   - **비주얼 껍데기(색·폰트·보더·이미지 URL 구조)는 건드리지 않는다.**

8. **자가 점검** — 가이드 §7 발송 전 체크리스트를 항목별로 확인. 특히: 이미지는 호스팅 URL(base64 금지), CTA는 `/vote`, 더보기·댓글 딥링크 매칭, 요약에 코멘트 안 섞임, 지어낸 내용 없음, 예고 주제가 새 주제인지.

9. **프리뷰 안내** — 사용자에게 `letters/<session>/digest.html`을 브라우저로 열어 검토하라고 안내한다(다크모드 포함). 발송은 사용자가 직접.

10. **ledger 갱신 (발송 후)** — 사용자가 "발송했다"고 하면 `letters/galpi-letters.json`의 `nextNumber`를 +1, `sent`에 이번 건 추가, 이번에 예고한 다음 달 주제를 `topicsUsed`에 추가하고 `nextTopic`을 갱신.

## 하지 않을 것

- Gmail `create_draft` 사용 금지 (HTML 렌더 깨짐 — 사용자가 직접 발송).
- 멤버별 "새 반응·댓글 개별 안내"(구 2차) 생성 금지.
- 템플릿의 색·타이포·레이아웃 임의 변경 금지 (가이드에 없는 비주얼 변경은 사용자 확인).
- 요약·댓글 인용에 본문에 없는 내용 추가 금지.
