# 갈피 레터 작성·발송 가이드

갈피(체크인 회고 모임의 사서)가 매달 보내는 **회고 다이제스트 레터**를 만들고 발송하는 실무 규칙 문서.
기획 배경은 [`retro-writing-participation.md`](./retro-writing-participation.md)에 있고, **이 문서는 "매달 어떻게 만드나"**만 다룬다.

> 이 레터를 만들 땐 이 문서 + [`../letters/`](../letters/)의 가장 최근 레터 HTML을 템플릿으로 함께 참고한다.

---

## 1. 이 레터는 무엇인가

- **장르:** 회고 **다이제스트**. "다들 이렇게 지냈어, 보러 와" + "다음 일정 투표해줘".
  (No.01 리마인더 — "회고 쓰러 와" — 와는 다른 장르다. 헷갈리지 말 것.)
- **발송:** HTML 파일을 만들고 **운영자가 직접 발송**한다. (Gmail `create_draft`는 HTML 렌더가 깨져서 쓰지 않는다.)
  - 전원 **공통 내용**이라 사실상 한 벌이면 된다. 멤버별로 나눌 이유가 생기면 그때 분리.

### 한 달에 두 번 — 1차 / 2차 (같은 구조)

같은 세션(달)에 이 다이제스트를 **두 번** 보낸다. **구조·템플릿은 완전히 동일**하고, 다른 건 타이밍과 그때의 데이터뿐이다.

|           | 1차                            | 2차                                                                 |
| --------- | ------------------------------ | ------------------------------------------------------------------- |
| 타이밍    | 회고 **끝난 다음 주**          | 그보다 뒤 (다음 모임 즈음)                                          |
| 존재 이유 | 회고 직후 다이제스트           | **늦게 쓴 회고·새 댓글이 반영된 최신본**                            |
| 만드는 법 | export 다시 돌려 **새로 생성** | export 다시 돌려 **새로 생성** (2차는 늦게 반영된 데이터가 더 많다) |

- 2차는 별도 로직이 아니다. **같은 절차를 나중에 한 번 더** 돌리면, 그 사이 추가된 글·댓글이 자연스레 들어온다.
- 발송 시점에 이미 **일정 투표가 끝났으면**, CTA 블록을 투표 대신 **만남 정보**(날짜·웨일 링크, No.01 레터의 만남 블록 재사용)로 바꿔도 된다. 그 외 구조는 그대로.

- **범위 밖(지금 안 함):** 멤버별 "새 반응·댓글 **개별 안내**" 섹션. 반응 데이터가 쌓이는 걸 한두 달 지켜본 뒤 2차에 붙일 후보다(§10). 그때를 위해 ledger에 **발송시각(`sentAt`)만 미리 기록**해 둔다.

## 2. 발송 플로우

1차·2차 모두 아래 절차가 **똑같다**. 차이는 도는 시점과 그때의 데이터뿐.

```
1. 데이터 뽑기      node scripts/export-letter-data.mjs <session>   → letters/<session>/data.json
2. 회차 판단        ledger에 이 세션 1차가 있으면 이번은 2차, 없으면 1차 (§6)
3. 요약 쓰기        data.json의 각 회고 본문 → 중립 요약 불렛 (§4)
4. 댓글 정리        comments[] → 딥링크 카드 (§5)
5. 다음 달 주제      DB(checkin_session_questions)에 없는 주제를 후보로 제안·승인해 예고 (§5-2) — 2차에선 승인된 주제 그대로
6. 템플릿 채우기     최근 digest 복사 → letters/<session>/digest-<회차>.html, 슬롯 교체 (§3)
7. 자가 점검        발송 전 체크리스트 (§7)
8. 프리뷰 → 검토     브라우저로 열어 눈으로 확인 (다크모드 포함)
9. 발송(운영자)      직접 발송
10. ledger 갱신      letters/galpi-letters.json — 번호·회차·발송시각·예고 주제 기록 (§6)
```

산출물 파일명: `letters/<session>/digest-1.html`(1차) · `digest-2.html`(2차).
(추적되는 템플릿은 [`../letters/_template.html`](../letters/_template.html) 하나다.
렌더된 레터 `letters/**/digest*.html`는 개인 내용 때문에 `.gitignore` 대상이라 로컬에만 남는다.)

## 3. 레터 구조 (고정 포맷)

위에서 아래로. 비주얼 껍데기(색·Georgia·마스트헤드·네이비 점선 보더·갈피 캐릭터)는 **고정**, 본문 텍스트만 매달 교체한다.

1. **마스트헤드** — `체크인 · 월간 회고 편지` / `No.NN / YYYY. MM`
2. **갈피 캐릭터** — `public/galpi/*.png` 중 매달 포즈 변주
3. **제목(h1)** — 이번 달 다이제스트 제목 (변주 가능)
4. **오프닝 멘트** — 3줄 내외, 계절·요즘 분위기, 갈피 목소리 (뉴스레터/라디오 오프닝 톤)
5. **인트로** — 이번에 몇 분이 글을 남겼는지 안부
6. **멤버별 회고 요약** — 카드 리스트 (§4). 이 레터의 핵심.
7. **이번 회고에 오간 댓글** — 댓글 리스트, 각 항목 클릭 시 해당 댓글로 딥링크 (§5)
8. **다음 달 공통 주제 예고** — 다음 회고 때 함께 답할 주제를 미리 흘림 (§5-2)
9. **다음 회고 일정 투표 CTA** — 버튼, 링크 **`/vote` 고정**
10. **푸터** — 모임 소개 + opt-out 한 줄("받기 싫어지시면 갈피한테 살짝 귀띔해주세요")

## 4. 멤버별 회고 요약 규칙

이 요약의 **목적**: 회고에 참여 못 한 사람도 남들 글이 어땠는지 한눈에 훑고, 마음이 가면 들어가서 원문을 읽고 반응하게 만드는 것. → 요약은 **미끼**지 대체물이 아니다.

- **형식:** 불렛 **2~3줄**. 각 줄은 짧게.
- **톤:** **중립·정보 전달.** 그 사람이 무슨 이야기를 썼는지 담담히 간추린다.
- **갈피 코멘트를 넣지 않는다.** ("~네요", "~같아요" 같은 감상·논평 금지.) 요약은 갈피의 감상 코너가 아니다.
- **원문 훼손 금지:** 본문에 없는 내용을 지어내지 않는다. 확실치 않으면 덜 쓴다.
- **더 보기 링크:** 각 카드 하단에 `articleUrl`(= `{site}/articles/{id}`). 원문으로 유도하는 게 핵심 CTA.
- **순서:** data.json의 `created_at` 순(먼저 쓴 사람부터). 특별한 이유 없으면 유지.

## 5. 이번 회고에 오간 댓글 규칙

- `data.json`의 `comments[]`를 그대로 보여준다. 각 항목 = "누가 → 누구의 글에" + 댓글 본문.
- **각 항목 클릭 → 해당 댓글로 딥링크:** `{articleUrl}#comment-{commentId}`.
  (앱이 `#comment-<id>` 해시를 받으면 그 댓글로 스크롤 + 잠깐 강조한다 — `CommentSection.tsx`.)
- 본문은 지어내거나 요약하지 않고 **원문 그대로**(길면 자연스러운 지점에서 자른다).
- 댓글이 **하나도 없으면 이 섹션 통째로 생략**한다.
- 순서는 `createdAt` 순.

## 5-2. 다음 달 공통 주제 예고 규칙

- 다음 회고 때 함께 답할 주제 하나를 **미리 흘린다**(답을 머릿속에 굴리게).
  이 레터는 회고 **후**에 나가므로, 이번 달 답변을 모으는 게 아니라 **다음 달 주제를 던지는** 자리다.
- 공통 질문의 단일 출처는 DB `checkin_session_questions`다(회고 세션당 하나, `status`: `proposed` → `approved`). 앱의 글 등록 화면·홈 배너도 여기서 읽는다.
- 예고하는 주제 = **다음 회고 세션**(이 레터의 session + 1개월)의 질문 row다.
- 주제는 DB에 이미 있는 질문(`node scripts/session-question.mjs list`)과 **겹치지 않게** 고른다(중복 방지). 후보 뱅크는 기획 §4-2.
- **1차:** 후보를 3개 제안하고 운영자가 하나를 고르면 `propose` → `approve`로 DB에 넣는다. 승인된 질문을 예고에 싣는다.
- **예시 한 줄**을 곁들여 "이 정도면 되는구나"를 보여준다 — 단 틀에 가두지 않을 만큼만.
- **2차에선 주제를 새로 고르지 않는다.** 다음 회고 세션에 이미 승인된 질문을 **그대로** 싣는다. (2차는 1차의 최신본이므로 주제도 같아야 한다.) 승인된 질문이 없으면 임의로 고르지 말고 운영자에게 묻는다.

## 6. ledger — `letters/galpi-letters.json`

레터 번호·회차·발송 이력을 관리한다. **공통 질문은 이 파일이 아니라 DB에서 관리한다**(§5-2).

- `nextNumber`: 다음 레터의 No. — 발송 후 +1. (1차·2차 각각 자기 번호를 갖는다.)
- ~~`topicsUsed` · `nextTopic`~~: DB `checkin_session_questions`로 이관했다. 스킬은 더 이상 읽지도 쓰지도 않는다(파일에 남아 있어도 무시).
- `sent[]`: 발송 이력. 각 항목: `number`(No.), `session`, `round`(`1`|`2`), `sentAt`(ISO 발송시각), `topic`(예고한 질문 문장 — 기록용).
  - **회차 판단:** 이번 세션에 `round: 1`이 이미 있으면 이번은 **2차**, 없으면 **1차**.
  - **`sentAt`은 지금은 안 쓰지만** 미래의 "새 반응·댓글" 섹션(§10)이 "이 시각 이후 달린 것"을 골라낼 기준이 된다. 그래서 미리 남긴다.

## 7. 발송 전 체크리스트

- [ ] **이미지는 base64 아님 — 호스팅 URL(`https://monthly-checkin.vercel.app/galpi/*.png`).** base64 인라인은 Gmail 102KB 클리핑으로 하단 잘림.
- [ ] **CTA 링크 = `/vote`** (다음 일정 투표). 회고 작성 페이지 아님 — 이 레터는 "다음 일정" 유도다. (예외: 2차인데 투표가 이미 끝났으면 만남 정보 블록으로 교체 — §1)
- [ ] **더 보기 링크 = 각 글 `articleUrl`** 정확히 매칭됐는지.
- [ ] **댓글 딥링크 = `{articleUrl}#comment-{commentId}`** 각 댓글에 맞게 매칭됐는지.
- [ ] 요약에 **갈피 코멘트가 섞이지 않았는지** (§4).
- [ ] 서술 텍스트에 **사서 메타포**(서가·자리·보관·꺼내읽다)가 남아 있지 않은지 (§8).
- [ ] 본문에 **없는 내용을 지어내지 않았는지** (요약·댓글 인용 모두).
- [ ] 다음 달 예고 주제가 DB `checkin_session_questions`에 **승인된 질문**으로 있고, 다른 회차와 겹치지 않는지.
- [ ] 마스트헤드 **No.NN / 년.월**이 맞는지.
- [ ] opt-out 한 줄이 부드럽게 남아 있는지.
- [ ] **다크모드 렌더링** 확인(크림 배경 강제 반전 시 투명 PNG 충돌).
- [ ] 한글은 Georgia 폴백 → 산세리프. "세리프 손편지" 무드는 라틴에만 실린다(그대로 OK).

## 8. 갈피 목소리 (요약 — 상세는 기획 §4-3)

레터의 **서술 텍스트**(오프닝·인트로·CTA 안내·서명)에만 적용. **요약 불렛엔 적용하지 않는다**(§4).

- 자기 지칭 **"저 / 제가"**. 자기 이름을 3인칭으로 쓰지 않는다.
- 말끝 `~예요 / ~해요 / ~할게요`. 느낌표 절제.
- 이모지 1~2개(🔖 ✉️ 🌙 등), 이모지 앞엔 한 칸 띄우기. 없어도 된다.
- 차분하고 다정하게. 재촉하지 않는다.

### 사서 메타포는 쓰지 않는다 (갈피 편지 전 종류 공통)

갈피가 **사서인 건 설정이지 말버릇이 아니다.** 편지에서 그 설정을 소리 내어 설명하지 않는다.

- **금지:** 서가에 보관해뒀어요 · 자리를 비워뒀어요 · 자리는 그대로 둘게요 · 한 장씩 꺼내 읽었어요 ·
  치우지 않았어요 · 같은 칸에 열어뒀어요 · 자리를 잡아둘게요
- 한두 번이면 분위기지만, 편지마다 반복되면 **캐릭터를 연기하는** 것처럼 읽힌다.
- 특히 "**자리를 비워뒀다**" 계열은 **"당신이 없었다"를 전제**하는 문장이라, 안 쓴 사람에게 은근한 압박이 된다.

|         | 안 됨                                  | 됨                             |
| ------- | -------------------------------------- | ------------------------------ |
| 지난 글 | 「…」는 서가에 잘 보관해뒀어요         | 「…」는 잘 읽었습니다          |
| 안내    | 8월 회고 자리도 같은 칸에 열어뒀습니다 | 8월 회고도 이제 쓰실 수 있어요 |
| 투표    | 모아서 자리를 잡아둘게요               | 모아서 일정 정리해둘게요       |
| 서명    | 천천히 오세요. 자리는 그대로 둘게요    | 그럼 다음 회고 때 봬요         |

**담백하게.** 꾸미는 말보다 사실과 질문을 쓴다.

> 기획 문서(`retro-writing-participation.md` §4-3)의 "사서 어휘" 항목은 이 규칙으로 대체됐다.
> 갈피의 **이름·정체성**(돌아올 자리를 표시하는 책갈피)은 그대로 유지된다 — 편지에서 말로 풀지 않을 뿐이다.

## 9. 데이터 소스 — `scripts/export-letter-data.mjs`

- service*role 키로 RLS 우회, **읽기 전용**. `.env`의 `SUPABASE_SERVICE_ROLE_KEY` 필요(`VITE*`프리픽스 없이,`.gitignore`됨).
- 실행: `node scripts/export-letter-data.mjs <session>` (예: `2026-07`). 세션이 안 맞으면 존재하는 세션 목록을 알려준다.
- 출력 `letters/<session>/data.json`:
  - `retrospectives[]`: `id, title, nickname, contentType, articleUrl, contentMarkdown, createdAt`
  - `comments[]`: `retrospectiveId, nickname, body, createdAt`
  - `members[]`: `nickname, email` (전체 로스터 — 누가 안 썼는지·수신자 파악용)

## 10. 향후(지금 안 함)

- **2차의 "새 반응·댓글" 개별 섹션** — 1차 `sentAt` 이후 각 멤버 글에 달린 반응·댓글만 골라 "○○님 글에 이런 게 새로 달렸어요"로 안내. 반응 데이터가 쌓이는 걸 한두 달 지켜본 뒤 붙인다. 기준 시각(`sentAt`)은 지금부터 ledger에 기록해 둔다.
- 공통 주제 답변 전용 컬럼 도입(추출을 수기 대신 구조화).
- 모임 하루 전 넛지 레터(별도 장르).
