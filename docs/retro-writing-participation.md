# 함께 쓰는 체크인 — 회고 글 참여 활성화 기획

월간 체크인의 **회고 글 작성 참여율**을 높이기 위한 기획 문서.
"모임 참석"이 아니라 **"글을 쓰는 것"** 을 참여의 기준으로 본다.
모임 날 일정은 각자 어쩔 수 없지만, 글은 못 나와도 남길 수 있기 때문.

> 상태: 실행 중 · 최초 작성 2026-07-31 · 최종 수정 2026-07-31
> 이번 달(2026-07): 페르소나 갈피 + 첫 레터 확정. 발송 체크리스트 처리 후 발송 예정.

---

## 1. 배경

- 개발자 지인 7~8명이 3년 넘게 운영해온 월간 회고 모임. 온라인 중심(웨일), 연 1~2회 오프라인.
- 최근 회고 **글 작성** 참여가 저조. 매달 3명 안팎만 글을 남기는 경우가 잦음.
- 참석 인원 자체는 사전 일정 투표로 정해지므로 매달 다르고, 이건 자연스러운 일로 본다.
- **진짜 문제는 글마저 안 써서 "우리 함께 하고 있다"는 느낌이 옅어지는 것.**
- 이 모임의 정체성은 각 잡은 "개발자 회고"가 아니라, **한 달에 한 번 어떻게 지냈는지 나누는 안부 자리**에 가깝다. 해법도 이 온도에 맞춰야 한다.

### 이미 하고 있는 것

- 전 달 참여자에게 매달 마지막 주 **이메일 리마인더** 발송.
- 지난 회고 요약 + "지난 액션을 지켰는지" 같은 다음 회고용 맞춤 질문 포함.

## 2. 재진단 — 이건 "동기" 문제가 아니다

### 근거: 익명 투표 결과 (복수 선택, 7명 중 6명 응답)

| 항목                        | 표    |
| --------------------------- | ----- |
| 참여 못해도 글은 쓰자       | 3     |
| 가능하면 쓰되 강제는 no     | 3     |
| 글 대신 다른 형식으로 대체  | 1     |
| **참여 못하면 패스해도 ok** | **0** |

→ **아무도 "패스 OK"를 고르지 않았다.** 멤버들은 이미 "쓰자" 쪽으로 기울어 있다.
즉 설득해야 할 동기 문제가 아니라, **마찰 · 보상 없음 · 프레이밍**의 문제다.
전략은 "어떻게 설득하지?"가 아니라 **"어떻게 쉽고, 쓰면 뭔가 돌아오고, 안 나와도 낀 느낌이 들게 하지?"**

### 핵심 통찰: 글쓰기의 보상이 화상 모임 안에 갇혀 있다

- 모임은 한 사람당 10~15분씩 돌아가며 **발표**하는 형식. 그 자리에서 사람들이 들어주고 반응한다.
- 이 **실시간 반응이 글을 쓴 것에 대한 보상**이다.
- **모임에 못 나가면 이 보상이 통째로 사라진다.** 글은 올릴 수 있어도 발표할 자리도, 언급해줄 사람도 없다.
- 그래서 "어차피 못 나가면 발표도 못 하는데 글은 왜 써?"가 된다.
- 관찰: 대부분 **회고 전날~당일**에 몰아서 쓴다. 글쓰기 창이 모임에 딱 붙어 있다는 증거.

> 결론: 참석과 글쓰기의 커플링은 사실 **"보상이 모임 안에만 있다"**는 구조 문제다.
> 해법의 본질은 **보상을 페이지 위로 꺼내는 것.**

## 3. 해결 프레임 — 네 개의 축

| 채우려는 것                 | 장치                                                 |
| --------------------------- | ---------------------------------------------------- |
| **보상** (쓰면 돌아온다)    | 반응 기능 (좋아요·댓글) = 발표의 비동기 버전         |
| **마찰** (부담 없이 짧게)   | 월간 공통 주제 = 짧은 답을 정당화하는 형식           |
| **신호** (쓰게 만드는 넛지) | 이메일 톤 전환 (숙제 → 안부) + 모임 전날 가벼운 넛지 |
| **소속** (안 나와도 낀다)   | 모임 끝 "결석했지만 글 남긴 사람" 코너               |

## 4. 실행안

### 4-1. 반응 기능 (좋아요·댓글) — 우선순위 1

- **왜:** 화상 발표에서만 일어나던 반응을 페이지로 꺼낸다. 못 나온 사람도 "내 글 읽혔고 반응 받았다"를 얻는다.
- **타이밍 궁합:** 글은 당일에 몰려도 **좋아요·댓글은 그 다음 며칠에 걸쳐** 들어온다. 회고 페이지가 "계속 살아있는 공용 공간"이 된다. (글은 이미 상시 열람 가능한 구조라 궁합이 좋음)
- **확정 스펙 (2026-08 · [이슈 #50](https://github.com/Jiwook00/checkin/issues/50)):**
  - **글 좋아요는 넣지 않는다.** 정해진 소수 인원에선 좋아요 카운트가 무의미 → 대신 **슬랙식 이모지 반응**.
  - **반응 대상 = 글 + 댓글 둘 다.** 기본 이모지 5개(👍 👏🏻 🥹 😂 😄) 원탭 + `＋` 더보기 피커. 한 사람 여러 개 OK, 같은 이모지는 사람별 스택.
  - **표시 = 슬랙식 칩(이모지 + 숫자).** 반응한 사람 얼굴은 호버 툴팁으로. 랭킹/정렬 없음. (프리뷰 A/B/C 중 **B** 채택)
  - **댓글은 글에만, flat**(대댓글 없음).
  - **도달**: 웹 푸시 없음. 결석자에게 "네 글에 이런 말 달렸어"는 **레터 다이제스트**가 배달(§4-4). 인앱 배지는 phase-2 보류.
- **배치:** 상세 페이지(`/articles/:id`, `ArticleReader`)에서만 노출/자체 fetch — `App.tsx` 전역 fetch·목록 카드는 v1에서 안 건드림(VotePage가 responses를 자체 fetch하는 패턴과 동일).
- **데이터 모델:** `checkin_comments`(retrospective_id cascade) + `checkin_reactions`(polymorphic: target_type `retrospective`|`comment`). polymorphic이라 orphan 청소는 삭제 트리거로.

### 4-2. 월간 공통 주제 — 우선순위 1 (거의 무료)

- **왜 "한 줄 회고" 유도의 답인가:** "한 줄도 괜찮아요~"라고 애원하는 건 없어 보인다.
  대신 **짧게 답하는 게 자연스러운 형식**을 주면 된다. 공통 주제가 그 형식이다.
  "이번 달 자주 여는 앱?"엔 한 줄로 답해도 그게 완성된 답이다. 주제가 짧음에 정당성을 준다.
- **왜 "함께"를 만드는가:** 흩어진 회고 7개보다, **같은 질문에 대한 답 7개**가 "우리 다 이렇더라"가 된다.
- **운영:**
  - 매달 가벼운 공통 주제 하나. **회고 + 주제** 또는 **주제만** 써도 인정.
  - 주제는 개발 각 잡기보다 안부 자리의 온도에 맞게.
  - 처음엔 운영자가 밀고, 이후 **주제 정하는 사람 돌아가며**(→ 밀어붙임이 공동 소유로 전환).

#### 공통 주제 후보 뱅크

- 요즘 제일 자주 여는 앱 / 사이트
- 이번 달 산 것 중 최고 (또는 최악)
- 요즘 빠져 있는 것
- 저장만 해두고 아직 못 본 것 (영상·아티클·책)
- 이번 달을 색 / 날씨로 표현하면
- 최근에 나를 웃게 한 것
- 다음 달의 나에게 한마디
- 요즘 반복 재생 중인 노래 / 플레이리스트
- 이번 달 새로 안 사실 하나

### 4-3. 페르소나 — 갈피 (사서)

리마인더 메일과 넛지의 **발신 화자**. 운영자(대니)가 아니라, 매달 찾아오는 캐릭터가 멤버 모두에게 보내는 편지로 통일한다.

- **이름 / 정체성:** **갈피** — 체크인 회고 모임의 **사서**. 이름은 중의적이다: _돌아올 자리를 표시하는 책갈피_ + _갈피를 잡다(방향을 찾다)_. 매달 한 통의 편지를 보내고, 지난 회고를 보관·정리하고, "돌아올 자리"에 갈피를 꽂아둔다.
- **왜 페르소나인가:** ① 발송 주체를 운영자에게서 떼어내 부담을 없앤다. ② "지난달 이야기를 꺼내주는" 개인화 훅이 **사서의 본업**이라, 참견이 아니라 캐릭터의 자연스러운 행동이 된다.
- **성격 / 말투:** 차분하고 다정하다. 재촉하지 않고 조용히 챙긴다. **존댓말을 쓰되 친근하게.**
- **목소리 스펙 (확정):**
  - 자기 지칭은 **"저 / 제가"**. ~~"갈피가 ~해뒀어요"~~ 처럼 자기 이름을 3인칭으로 쓰지 않는다(오글거림).
  - 말끝 `~예요 / ~해요 / ~할게요`. 느낌표 절제.
  - **사서 어휘**: 보관해뒀어요 · 꺼내읽었어요 · 자리를 표시해둘게요.
  - 이모지 1~2개(🔖 ✉️ 🌙 🍚 등). 이모지 앞엔 한 칸 띄우기.
  - **매달 바뀌는 오프닝 멘트(3줄 내외)**로 편지를 연다 — 뉴스레터/라디오 오프닝 톤(계절·요즘 분위기). 갈피 편지의 고정 포맷.
- **비주얼 룩 (확정):** 손으로 그린 마커 라인, **테라코타 단색 외곽선 + 네이비 점선(스티플) 텍스처 + 크림 배경**, 점 눈 + 작은 미소, 책갈피(리본) 실루엣. Recraft로 제작. 미니멀·따뜻·카페/책방 정서.
- **에셋 (확정):** `public/galpi/`에 표정·포즈 4종 보관 — `offering-letter`(편지 건네기·이메일 헤더용), `waving-hello`, `peeking-out`, `holding-pencil`. 투명 PNG. 매달 포즈를 바꿔 변주.
  - **원칙:** 벡터화 불필요(손그림 텍스처가 벡터와 상성 나쁨). 고해상도 PNG를 마스터로 보관. 앱 아바타·파비콘도 이 PNG로 커버.

### 4-4. 이메일 톤 전환 — 우선순위 1 (무료)

- **문제 제기:** 지금 이메일의 "지난 액션 지켰나요?"는 **각 잡은 회고의 감사(audit) 톤**이다.
  이 모임은 그런 자리가 아니라고 했으니, **이메일이 오히려 "숙제" 프레임을 강화**하고 있을 수 있다.
- **전환:**
  - 감사 톤 → **궁금함 톤.** "지난달 너 OO 하겠다 했잖아, 그 뒤로 어때?"
  - **이번 달 공통 주제를 미리 흘려** 답을 머릿속에 굴리게.
  - **지난달 글에 달린 반응을 한두 개** 담아 보상·온기를 메일 안으로 회수. (반응 기능 이후)
  - **타이밍:** 월말 맞춤 메일 + **모임 하루 전 짧은 넛지** 한 번 더. ("내일이야, 한 줄이라도 남겨두면 얘기하기 좋아.")
- **발신 주체 / 말투:** 화자는 운영자가 아니라 페르소나 **갈피**(→ §4-3). 존댓말을 쓰되 친근하게. (멤버끼리 서로 반말은 하지 않는 사이)
- **주제엔 가벼운 작성 예시 한두 줄**을 곁들여 "이 정도면 되는구나"를 보여준다 — 단 틀에 가두지 않을 만큼만.

#### 갈피의 첫 레터 (2026-07 · No.01)

- **HTML 이메일로 발송.** 디자인 방향: **손편지 / 에디토리얼** — Georgia 세리프(라틴), 상단 마스트헤드 `체크인 · 월간 회고 편지 / No.01 / 2026. 07`(넘버링으로 "매달 온다" 각인), 네이비 점선 보더가 갈피 캐릭터 텍스처와 호응, 테라코타·크림 팔레트.
- **첫 레터 필수 요소:** 갈피 소개 + "오늘부터 매달 편지로 찾아온다"는 예고. ("보관소에 몇 년치가 쌓여서 가끔 꺼내드리는 게 낫겠다 싶었어요"로 자연스럽게 정당화)
- **레터 구조(고정 포맷):** 오프닝 멘트 3줄 → 소개/안부 → 개인화 콜백(지난달 글 꺼내읽기) → 이번 달 공통 주제(강조 블록 + 예시) → 낮은 문턱 안내 → 만남 정보(날짜·웨일 링크) → CTA 버튼 → 서명.

##### 발송 전 체크리스트 (재사용)

- [ ] **이미지는 base64가 아니라 호스팅 URL로.** 인라인 base64는 **Gmail 102KB 클리핑**에 걸려 하단이 잘림. `https://[배포도메인]/galpi/*.png` 참조로. (base64는 클로드 아티팩트 프리뷰 전용)
- [ ] **CTA 링크 = 회고 작성 페이지**로. (일정 투표 `/vote` 아님 — 목적지 혼동 주의)
- [ ] 개인화 콜백은 **수신자별 수기/템플릿**. 7~8명 규모라 감당 가능하지만 시간 비용 인지.
- [ ] opt-out 한 줄은 부드럽게 여지를 남긴다("받기 싫어지면 갈피한테 귀띔해주세요").
- [ ] 발송 전 **다크모드 렌더링** 확인(크림 배경 강제 반전 시 투명 PNG 충돌).
- [ ] 한글은 Georgia가 안 먹고 산세리프 폴백 — "세리프 손편지" 무드는 라틴에만 실린다는 점 인지(그대로 OK).

### 4-5. 결석자 코너 — 모임 미세 조정

- 발표 형식은 유지하되, **모임 끝 5분: "이번 달 못 나왔지만 글 남긴 사람들"** 코너.
- 그 글 한 꼭지 같이 읽고 한마디씩. → 발표는 못 했어도 자기 글이 그 방에서 다뤄졌다는 걸 알게.
- **"안 나와도 낀다"를 구조로** 만든다 (투표에서 6명이 원한 바로 그것).

## 6. 의사결정 원칙 — 설문할까, 그냥 밀까

- **가치·규범 결정**(예: "못 나와도 쓰자")은 합의가 필요 → 설문이 맞고, 이미 했다. **명분은 확보됨.**
- **가볍고 되돌릴 수 있는 실험**(공통 주제·이메일·반응)은 **설문 대상이 아니다.**
  - 추상적 질문("공통 주제 어때요?")엔 미지근한 답만 온다. **실물 주제를 툭 던지면** 사람들은 개념이 아니라 실물에 반응한다.
  - 작은 걸 매번 투표에 부치면 안부 자리가 행정처럼 식는다.
  - 운영자가 가벼운 이니셔티브를 쥐는 게 자연스럽고, 행동을 모델링한다.
- **원칙:** _형식은 밀되, 내용은 초대한다._ "이번 달 한번 이렇게 해볼까?"로 실행하며 제안하고, "별로면 말해줘" 한 줄로 문만 열어둔다.
- **주의:** 반응+주제+이메일+결석자코너를 한 메일에 다 쏟으면 무거운 리론칭이 되어 따뜻한 결을 깬다. **이번 달엔 공통 주제 하나만.**
