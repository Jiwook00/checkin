# 0011 - 디스코드 봇은 HTTP Interactions만 쓰고 서명으로만 받는다

- 상태: 승인됨
- 날짜: 2026-11-13
- 관련 이슈: #101 (에픽 #107), 후속 #102·#103·#104·#105·#106
- 관련 커밋: 2805556

## 컨텍스트

웹훅(ADR 0010)은 채널에 글을 올리는 단방향 경로다. DM, 서버 이벤트, 슬래시 커맨드를 쓰려면 봇이 필요하다. 봇을 받는 방식은 둘이다. 상시 접속(Gateway)을 유지하는 서버를 두거나, Discord가 우리 HTTP 엔드포인트를 부르게(Interactions) 하는 것이다.

정할 것은 셋이다.

1. 봇을 어디서 받는가
2. 그 엔드포인트를 어떻게 지키는가
3. 봇에 어떤 권한을 주는가

## 결정

### HTTP Interactions만, Edge Function `discord-interactions` 하나로

- Discord → `discord-interactions`. Gateway는 쓰지 않는다. 상시 접속 서버가 필요한 기능(음성 출석, 채팅 아카이브)은 에픽 #107의 범위 밖이다.
- 봇이 Discord API를 부르는 일(서버 이벤트 #103, DM #104·#105)은 봇 토큰으로 REST만 쓴다. Gateway 연결이 필요 없다.

### 서명이 유일한 관문

- Discord가 부르므로 `verify_jwt = false`(`config.toml` + 배포 `--no-verify-jwt`)다. Ed25519 서명 검증만 통과시킨다.
- **Web Crypto(`crypto.subtle`의 `Ed25519`)로 검증한다.** 유일한 관문을 외부 코드에 맡기지 않는다.
- **받은 바이트 그대로 검증한다.** `req.arrayBuffer()`로 받은 원문 앞에 `X-Signature-Timestamp`를 붙여 검증하고, 통과한 뒤에만 같은 바이트를 JSON으로 읽는다. 파싱 후 다시 직렬화하면 키 순서·공백이 달라져 서명이 깨지고, `req.text()`는 잘못된 UTF-8을 바꿔 버린다.
- **타임스탬프가 현재와 ±5분 넘게 차이 나면 거절한다.** 서명이 타임스탬프를 덮으므로 위조는 안 되지만, 캡처한 요청을 그대로 다시 보내는 것은 서명만으로 막지 못한다. 창을 두면 재생 가능한 시간이 5분으로 줄어든다.
- 서명 없음·형식 오류·불일치·시각 초과는 모두 401이고 이유를 구분하지 않는다. 공개키가 없거나 형식이 틀리면 모든 요청을 500으로 거절한다.
- body와 헤더는 로그·응답에 남기지 않는다.

### 최소 권한

| 항목                 | 값                                      | 근거                                                                          |
| -------------------- | --------------------------------------- | ----------------------------------------------------------------------------- |
| Scopes               | `bot`, `applications.commands`          | 봇 초대, 슬래시 커맨드 등록(#106)                                             |
| 이벤트 만들기        | Create Events                           | #103 서버 이벤트. 봇이 만든 이벤트는 수정·삭제할 수 있어 Manage Events 불필요 |
| 채널 보기, 연결      | View Channels, Connect                  | 음성 채널 이벤트를 만들 때 그 채널에서 요구된다                               |
| 채팅 권한            | 없음                                    | 채널 글은 웹훅, 커맨드 응답과 DM에는 채널 권한이 필요 없다                    |
| Privileged Intents   | 모두 끔                                 | Gateway를 쓰지 않는다                                                         |
| Public Bot / Install | 끔 / Guild Install만, Install Link None | 우리 서버 밖에 설치되지 않게                                                  |

권한 값은 `17592187094016`이다. 권한이 더 필요해지면 서버의 봇 역할에서 올린다.

### 시크릿

| 값                   | 위치                     |
| -------------------- | ------------------------ |
| `DISCORD_PUBLIC_KEY` | Edge Function 시크릿     |
| `DISCORD_BOT_TOKEN`  | Edge Function 시크릿에만 |

공개키는 비밀은 아니지만 바뀌면 관문이 바뀌므로 코드에 두지 않는다. 봇 토큰은 이 함수에서 쓰지 않고 #103·#104가 쓴다.

## 대안

- **Gateway 봇 서버.** 기능 제약이 없지만 상시 접속 프로세스를 호스팅·감시해야 한다. 1인 운영에 비해 과하다.
- **`tweetnacl`로 검증 (Supabase 예제 방식).** 유지보수가 멈췄고 CDN을 거치면 공급망 위험이 하나 늘어난다.
- **`@noble/ed25519`.** 감사받은 라이브러리라 Web Crypto가 안 될 때의 대안으로 둔다. 지금은 런타임이 Ed25519를 지원해서 쓰지 않는다.
- **interaction id로 중복 거절.** 재생을 완전히 막지만 저장소가 필요하다. 지금은 PING뿐이라 과하고, 상태를 바꾸는 커맨드가 생기면 그 커맨드에서 멱등성을 챙긴다.

## 알려진 한계

- 검증은 Supabase Edge Runtime의 Web Crypto에 기댄다. 런타임이 바뀌어 Ed25519가 빠지면 포털의 엔드포인트 검사가 실패한다. 그때 `@noble/ed25519`로 바꾼다.
- ±5분 안의 재생은 막지 못한다. TLS를 깨야 캡처할 수 있어 위험은 낮다.
- 지금은 PING만 받는다. 커맨드 처리는 #106에서 정한다.
